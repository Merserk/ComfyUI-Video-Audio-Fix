# ComfyUI Video Audio Fix

A compact ComfyUI custom node that restores a video's default audio track with
[FlashSR](https://github.com/jakeoneijk/FlashSR_Inference) (one-step versatile
audio super-resolution via diffusion distillation), merges it into the selected
MP4 or MKV container, saves the result, shows an inline video
preview, and provides a stacked spectrogram image output for before/after
comparison.

## Installation

1. Clone the repository into `ComfyUI/custom_nodes`:

   ```bash
   cd ComfyUI/custom_nodes
   git clone https://github.com/Merserk/ComfyUI-Video-Audio-Fix.git
   ```

2. Run `install.py` with the Python used by ComfyUI.

   Windows Portable, from the `ComfyUI_windows_portable` directory:

   ```bat
   .\python_embeded\python.exe .\ComfyUI\custom_nodes\ComfyUI-Video-Audio-Fix\install.py
   ```

   Standard installation example:

   ```bash
   cd ComfyUI/custom_nodes/ComfyUI-Video-Audio-Fix
   python install.py
   ```

   The installer will:

   1. Create `.venv` inside this repository.
   2. Install all FlashSR/node packages into that `.venv` only.
   3. Detect and reuse ComfyUI's existing Torch/CUDA/ROCm build.
   4. Install the upstream `FlashSR_Inference` source (which contains the
      `FlashSR` and `TorchJaekwon` packages).
   5. Verify FlashSR with a private runtime import check.
   6. Download and validate a private portable FFmpeg and FFprobe pair. The
      validator supports current FFmpeg filter-table formats and automatically
      replaces an existing portable binary only when it is genuinely incompatible.

   Portable binaries are stored at:

   ```text
   ComfyUI/custom_nodes/ComfyUI-Video-Audio-Fix/bin/
   ```

   No administrator access or system `PATH` change is required.

3. Restart ComfyUI.

## Node

**Display name:** `Video Audio Fix`  
**Internal class:** `AudioVideoFix`

Inputs/widgets:

- `video` — ComfyUI `VIDEO`
- `filename_prefix` — output filename prefix
- `auto_download` — download the FlashSR checkpoints when missing
- `strength` — how much of the FlashSR-restored spectrum replaces the original
  audio (default `Full band`):
  - `Subtle` — keeps the original low-frequency content below an automatically
    detected crossover
  - `Balanced` — blends the restored audio in from 3 kHz up
  - `Full band` — uses the restored audio across the full spectrum
- `output_format` — final container/audio profile:
  - `MP4` — AAC, 48 kHz, target 320 kb/s
  - `MKV` — uncompressed signed 16-bit little-endian PCM, 48 kHz
- `precision` — FlashSR inference precision (default `FP32`):
  - `FP32` — full 32-bit inference with higher VRAM use
  - `FP16` — CUDA autocast for lower VRAM use and faster execution
- `artifacts_reductions` — preservation-first FFmpeg cleanup (default `On`):
  - `On` — conservative overlap-save de-clicking, a 10 Hz high-pass, a 23 kHz
    low-pass, exact sample-length restoration, and file-wide attenuation only
    when the cleaned signal would exceed -1 dBTP
  - `Off` — bypass the cleanup stage and use the reconstructed FlashSR result
    directly

Output:

- `video` — the processed file-backed ComfyUI `VIDEO`
- `image_spectrogram` — one stacked `IMAGE` preview containing the **before** and
  **after** spectrograms vertically, ready to connect to **Preview Image** or
  any other image node

The node itself shows only the video preview. The spectrogram comparison is
emitted through `image_spectrogram`, and the underlying PNG files are saved next
to the output video. Each graph automatically estimates its meaningful audio
bandwidth and selects a clean vertical ceiling such as 12, 16, or 24 kHz. The
`after` graph is generated by decoding the audio from the completed MP4/MKV, so
it includes the real effect of AAC encoding or 16-bit PCM quantization.

The node automatically uses the FlashSR one-step distilled diffusion model,
48 kHz output, 5.12-second chunks with smooth 4% overlap for short and long
videos, and preserves the original low-frequency content according to the
selected `strength`. The two bands are summed with a 4th-order Linkwitz-Riley
crossover, so the blend is spectrally flat (no phase-cancellation notch at the
crossover) and the restored audio stays sample-aligned with the video track.
When `artifacts_reductions` is enabled, the old NumPy/SciPy cleaner is not used.
The worker runs one preservation-first FFmpeg chain instead: `adeclick` in
overlap-save mode (`window=10`, `arorder=8`, `threshold=20`, `burst=1`), fixed
10 Hz and 23 kHz
boundary filters, exact frame-count restoration, and `loudnorm` used only as a
true-peak meter. If the measured cleaned signal is hotter than -1 dBTP, one
constant `volume` adjustment is applied to the complete file; otherwise no gain
change is made. The completed WAV is measured again and its sample rate, channel
count, and frame count are verified. There is no noise-profile estimation,
gating, declipping, de-essing, tonal EQ, compression, excitation, stereo
decorrelation, silence removal, or loudness normalization.

## Output formats and preservation

- The encoded video stream is copied without re-encoding (`-c:v copy` through
  the global stream-copy mapping).
- Resolution, frame rate, pixel format, chapters, metadata, subtitles, and other
  tracks are copied when the selected destination container supports them.
- The restored audio keeps the selected source track's language, title, start
  offset, and disposition.
- `MP4` uses 48 kHz AAC with a requested target bitrate of 320 kb/s.
- `MKV` uses 48 kHz `pcm_s16le`, which is the same uncompressed 16-bit PCM sample
  representation commonly stored in WAV, but it is stored directly as a
  Matroska audio track rather than as a WAV file inside the MKV.

MP4 supports fewer stream types than MKV. When a source video, subtitle,
attachment, or other copied stream cannot be represented in MP4, the node stops
with a clear error and recommends selecting MKV instead of silently dropping or
transcoding the stream.

## Model

With `auto_download = true`, the three FlashSR checkpoints are downloaded from
`jakeoneijk/FlashSR_weights` (a Hugging Face dataset, about 3.3 GB total) to:

```text
ComfyUI/models/flashsr/
    student_ldm.pth   (1.03 GB)
    sr_vocoder.pth    (0.63 GB)
    vae.pth           (1.66 GB)
```

With `auto_download = false`, no network request is made and the files must
already exist at those paths.

## Processing

1. Resolve or materialize the input `VIDEO`.
2. Select the default audio track, or the first audio track when no default is set.
3. Extract it as 48 kHz floating-point WAV.
4. Launch the isolated `.venv` FlashSR worker.
5. Restore each channel in overlapping 5.12 s chunks (the model has a fixed
   input length of 245,760 samples); LFE channels are passed through.
6. FlashSR internally lowpasses the input (automatic cutoff detection) and
   regenerates the full-band signal in a single diffusion step.
7. Preserve original low-frequency content and use FlashSR for restored highs
   according to the selected `strength` (4th-order Linkwitz-Riley crossover);
   match the exact source audio sample length.
8. When `artifacts_reductions = On`, run the FFmpeg artifact guard: apply
   conservative overlap-save `adeclick`, fixed 10 Hz high-pass and 23 kHz
   low-pass filters, restore the exact original sample length, measure true peak,
   and apply one constant file-wide attenuation only when required to finish at
   or below -1 dBTP. Measure and validate the completed WAV again.
9. Encode the cleaned track according to `output_format`: AAC 320 kb/s for MP4,
   or uncompressed signed 16-bit PCM for MKV.
10. Replace only the selected audio track and copy all compatible source streams.
11. Validate the container, copied video properties, restored codec, sample rate,
    and PCM bit depth where applicable.
12. Decode the restored track from the completed container and generate automatic
    before/after bandwidth spectrograms from the actual source and final audio.
